Setup & security

Bring your own credentials.

Monhood keeps provider access in your local environment. Nothing on this page asks you to paste a secret into the browser, commit it to Git, or share it with another user.

Required to run

Start with the one credential that powers token and chain data. The rest can be enabled as your workflow grows.

01

Clawby API key

Create a key at openclawby.com, then store it in CLAWBY_API_KEY inside your local .env file.

Required
02

Python runtime

Python 3.9+ is required. run.sh creates an isolated environment and installs the small runtime dependency set.

Required

Optional connections

These services unlock deeper reports, AI scoring, or notifications but are not needed for basic monitoring.

03

AI engine

Use a locally authenticated Claude Code or Codex CLI for scoring and deep report generation.

Optional
04

Telegram bot

Add a bot token and chat ID in the Admin window when you want threshold alerts.

Optional
05

Google Chrome

Needed on macOS when the report renderer converts generated HTML into a PDF.

Optional

Safe local setup

Keep secrets out of source control. The repository already ignores the local environment file and runtime outputs.

Never use a GitHub token, Clawby key, Telegram token, or AI provider key in client-side HTML. Publishable Clerk keys are intentionally safe to expose; all other credentials stay server-side.
cp .env.example .env CLAWBY_API_KEY=pk_your_key_here bash run.sh
